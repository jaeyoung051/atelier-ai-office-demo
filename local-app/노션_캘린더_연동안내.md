# 노션 업무 일정 캘린더

2026-11-22 구현. 기존 공개 시안에는 적용하지 않으며 로컬 앱에서만 실행합니다.

## 구현한 화면

- 공정·발주·견적 상단: 공사일정/발주일정 월별 캘린더. 로컬 공정표 각 단계, 발주 권장일, 자재 필요일도 표시합니다.
- 업무 보드 최하단: 위 두 유형을 제외한 모든 일정. 현장일정, 근무, 개인일정, 고객미팅, 실측, 도면/견적/렌더링/계약, 대표협업/거래처, 교육 및 신규/미분류 포함.
- 일요일 시작 6주, 이전/다음 달·오늘·현장 필터·날짜 없는 일정·상세 보기.
- 여러 유형 중 공사/발주가 포함되면 현장 캘린더에만 표시합니다.
- 기간 일정은 날짜별 반복 표시. 공정표 평일 작업은 토·일·지정 휴무일 제외, 달력일 작업은 모두 표시합니다.
- 로컬과 노션은 출처 표시하며 동일 내용도 임의로 합치지 않습니다. 검토 중 문서는 ‘검토 필요’로 표시합니다.

## 현재 연결 상태

사용자가 제공한 주소는 비공개 페이지여서 로그인 없이 데이터베이스 속성을 읽을 수 없었습니다. 실제 노션 토큰/데이터 소스 ID가 아직 없으므로 실제 일정 동기화는 미완료입니다. 스크린샷의 개인 일정은 임의로 DB에 입력하지 않았습니다.

## PC에서 연결

1. 노션의 내부 연결 관리에서 해당 워크스페이스의 연결을 생성하고 콘텐츠 읽기 권한만 부여합니다. 쓰기 권한은 필요하지 않습니다.
2. 원본 ‘업무 일정’ 데이터베이스에 해당 연결의 접근을 허용합니다. 보기 링크가 있는 상위 페이지만 아니라 원본 DB에 권한이 있어야 합니다.
3. 원본 데이터 소스 메뉴에서 데이터 소스 ID를 복사합니다. 페이지 URL의 ID와 데이터 소스 ID는 다를 수 있습니다. DB ID만 있다면 Notion API의 데이터베이스 조회 결과 data_sources에서 대상 ID를 확인합니다. 여러 데이터 소스 중 업무 일정 원본을 선택합니다.
4. 이 폴더의 `.env`에 아래 설정을 추가합니다. 토큰은 채팅/스크린샷/공개 GitHub에 보내지 마세요.

```dotenv
NOTION_TOKEN=PC에서만_입력
NOTION_CALENDAR_DATA_SOURCE_ID=업무_일정_원본_데이터소스_UUID
NOTION_CALENDAR_DATE_PROPERTY=날짜
NOTION_CALENDAR_TYPE_PROPERTY=일정유형
NOTION_CALENDAR_PROJECT_PROPERTY=현장
```

필수 속성: 제목(title), 날짜(date), 일정유형(select 또는 multi_select). 현장은 선택 사항이며 텍스트/선택/제목을 읽습니다. 실제 속성 이름이 다르면 설정을 바꾸세요. 현장이 관계형이면 상세의 ‘앱 현장 연결’에서 수동 연결합니다. 이름이 앱의 현장 이름과 정확히 일치하고 유일할 때만 자동 연결합니다. 자동 연결로 되돌리기는 명시적인 연결을 삭제하며 같은 이름이 있으면 다시 자동 연결됩니다.

5. Mac 실행·종료 파일 또는 `npm run app:stop`, `npm run app:start`로 재시작합니다.
6. 캘린더의 ‘노션 일정 가져오기’를 누릅니다. 성공하면 마지막 가져오기 시간이 표시됩니다.

동기화는 **노션 → 로컬** 단방향, 버튼을 눌러 수행합니다. 앱에서 일정 내용을 노션으로 수정/삭제하지 않습니다. 노션 일정의 생성·날짜/유형 수정은 노션에서 한 뒤 다시 가져옵니다. 월 이동·다시 조회는 로컬 저장본만 읽습니다. 연결 설정을 바꾸면 기존 다른 소스의 기록은 표시하지 않습니다.

## 저장·복원 및 제한

- migration: `backend/migrations/013_notion_calendars.sql`
- `notion_calendar_events`: 외부 ID PK, 제목/유형/날짜/원본 날짜값/원본 링크/현장명/소스/수정시각. 날짜 범위 인덱스.
- `notion_calendar_project_links`: 일정 FK 삭제 CASCADE, 프로젝트 FK 삭제 RESTRICT. 앱 내부 매핑.
- `notion_calendar_sync`: 마지막 성공 시각·건수·소스. 토큰은 저장하지 않습니다.
- 전체 SQLite 백업에 저장 일정과 현장 연결도 포함됩니다. `.env`는 백업/배포에 포함하지 않으므로 이전 PC에서 토큰을 다시 설정합니다. 노션 비공개 일정도 개인정보일 수 있으므로 개인 DB를 공개 호스팅/GitHub에 올리지 마세요.
- 전체 페이지 수신·검증 성공 후 하나의 트랜잭션으로 교체합니다. 실패하면 이전 저장본과 매핑을 유지합니다. 원본에서 삭제/휴지통 처리된 일정은 다음 성공 동기화 때 로컬 캐시에서도 제거됩니다. 과거 캐시가 필요하면 먼저 백업하세요.
- 최대 100페이지, 10,000건. 초과/잘못된 응답은 실패 처리. 요청 20초 제한, 429 최대 3회 제한 재시도. 원문 오류/토큰을 UI에 노출하지 않습니다.
- 날짜만 있는 범위는 종료일 포함. 시각이 있으면 Asia/Seoul 날짜로 표시하며 종료 시각이 속한 날도 포함합니다. 정확한 시각은 상세에 원본 ISO로 표시합니다. 반복 규칙/알림/자동 주기 동기화/양방향 편집은 이번 범위 밖입니다.

## API와 검증

`GET /api/calendars?scope=operations|work&month=YYYY-MM&project_id=...`

`GET /api/notion-calendar/status`

`POST /api/notion-calendar/sync` (빈 JSON 객체)

`POST /api/notion-calendar/:id/project` (`project_id`, null은 자동 연결 복귀)

전체 32개 테스트 통과. 신규 테스트는 월 경계/윤년/서울 시각, 전체 유형 분류, 페이지네이션, 실패 시 기존 데이터 유지, 삭제 반영, 현장 연결/해제, 날짜 없음, 요청 제한 재시도, 인증/속성 검증, 로컬 공정/발주 격리를 확인합니다. 노션 API는 가짜 응답으로 검증했으며 실제 계정 연결 검증은 남아 있습니다. 실제 브라우저에서 두 캘린더와 월 이동, 미연결 안내 표시를 확인했습니다.

공식 참고: https://developers.notion.com/reference/query-a-data-source 및 https://developers.notion.com/guides/get-started/upgrade-guide-2025-09-03 (명시적 API 버전 2025-09-03 사용).
