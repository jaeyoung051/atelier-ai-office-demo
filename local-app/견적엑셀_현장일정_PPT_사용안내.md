# 견적 엑셀 → 현장 공정표·발주 일정 참고표

## 사용 순서

1. 공정·발주·견적의 **자재·단가 관리 바로 아래**에서 대상 현장과 `.xlsx` 견적서를 선택하고 ‘엑셀 읽기’를 누릅니다. ‘입력 양식 다운로드’로 가상 예시가 있는 양식을 받을 수도 있습니다.
2. 시트·제목 행·열을 연결합니다. 품목명은 필수이고 규격, 수량, 단위, 공정, 작업일수, 납기(평일), 공급처는 선택입니다. 표 위에 제목이 있으면 제목 행 번호를 바꾸세요.
3. ‘품목 확인’에서 원본 행 번호와 값을 대조합니다. 빈 품목과 정확한 합계/소계 이름의 행은 제외합니다. 추가로 필요 없는 행은 체크를 해제합니다. 복잡한 병합·복수 표·단가만 있는 행은 정리해 입력하세요.
4. 착공 예정일·자료 제목을 넣고 ‘현장 일정 초안 만들기’를 누릅니다.
5. 공정명·시작일·일수·평일/달력일·휴무일을 확인합니다. 같은 공정은 한 번으로 묶고 견적 순서대로 처음 배치합니다. 시작일을 따로 조정하면 병행 작업을 표현할 수 있습니다. 한 공정의 기간을 수정해도 뒤 공정의 시작일은 자동 이동하지 않으므로 함께 확인하세요.
6. 품목마다 자재 사용 공정·납기·여유일을 확인합니다. 인건비·서비스 등은 ‘발주 대상’ 체크를 해제합니다. 품목 자체는 견적 근거로 보존됩니다.
7. ‘수정 저장·미리보기’로 날짜를 다시 계산합니다. 양생처럼 주말에도 이어지는 작업은 ‘달력일’을 체크하세요. 기본 납기는 비어 있으면 0일, 기간은 기본 1일이고 이 가정을 따로 기록합니다. 계약/공급처에 확인한 실제 값으로 수정하세요.
8. 확인란을 체크하고 ‘확인하고 승인’을 누릅니다. 승인본 PPT는 현장 카드에서 다시 내려받을 수 있습니다. 미승인본도 ‘검토용 초안’ 표시로 다운로드할 수 있습니다.

엑셀 분석·초안·PPT 생성은 로컬에서 수행하며 Gemini/Claude로 전송하지 않습니다. AI가 시공 기간을 추측하는 방식이 아닙니다. 이 기능의 API 비용은 없습니다. 실제 발주는 실행하지 않습니다.

## 생성되는 PPT

사진을 참고한 가로 A4 비율의 일~토 달력입니다. 주황 요일, 연녹색 날짜 행, 일요일/지정 휴무일 빨간 날짜, 연속 같은 공정 구간 표시, 하단 변동 안내가 들어갑니다. 달력은 6주 단위로 이어지며 기간이 길면 여러 장이 됩니다. 편집 가능한 표로 만들고, 별도 공정 상세·발주 참고표·견적 품목 대조·확인 사항을 포함합니다. 긴 공정명·동일 날짜 다수 작업은 달력에서 공정 번호로 요약하고 상세표에는 전체 이름을 남깁니다.

참고 사진의 실제 주소·로고·출입 정보는 앱이나 예시 PPT에 복사하지 않았습니다. 폰트는 맑은 고딕을 요청하며 Mac의 글꼴 환경에서는 대체 글꼴로 보일 수 있습니다. PowerPoint/Keynote에서 글꼴은 바꿀 수 있습니다.

## 프로젝트별 화면

- 왼쪽 ‘진행 전·준비 필요’: 계약 완료 후 공정표 또는 발주 일정 작성·승인이 남은 현장.
- 오른쪽 ‘진행 중’: 실제 공사 진행 현장, 또는 공정·발주 일정 자료가 승인된 현장. 공사 진행 현장에 미완료 자료가 있으면 필요한 작업을 표시합니다.
- 기존 승인 공정표와 승인/발주/입고 상태 발주 문서가 모두 있는 현장도 준비 완료로 분류합니다. 계약 단계 자체는 자동 변경하지 않습니다.
- 승인한 일정 묶음은 현장 카드의 파일 목록, 미승인/반려본은 ‘현장 자료 보기’에 정리됩니다.
- 기존 저장 문서는 현장을 선택해 ‘견적/공정/발주’로 접어서 조회합니다. 업무 보드 검토함도 현장별로 묶었습니다.
- 승인한 새 일정은 공사·발주 캘린더에 반영됩니다. 별도 실제 발주 주문이나 기존 견적/공정 문서를 자동 수정하지 않습니다. 로컬 수동 문서와 일정 묶음을 중복 입력하면 양쪽 출처가 함께 표시됩니다.
- 수정 저장은 새 버전 + 재검토 상태입니다. 과거 승인 스냅샷은 유지하며 현재 버전의 승인 표시를 제거합니다. 완료 현장 보관 기준은 공정 화면의 기존 기준(공사완료+포트폴리오 등록)을 유지합니다.

## 고객·현장 관리 ‘완료된 현장’

고객 관리 탭에 별도 버튼을 추가했습니다. 기준은 **현장에 연결된 ‘완공 포트폴리오’ 용도의 프롬프트가 생성 성공(ready)한 경우**입니다. 제안서용, 실패, 생성 중, 현장 미연결 자료는 제외합니다. 생성 완료와 원본 검토 완료를 구분해서 표시하며, 생성 성공한 자료가 있으면 고객 관리 일반 목록에서 완료 목록으로 분리합니다. 물리적인 공사 단계는 임의 변경하지 않습니다.

마케팅의 ‘Claude PPT용 프롬프트 만들기’에서 현장과 용도를 지정하세요. 예전 자료는 연결 정보가 없으므로 각 결과의 ‘현장·용도 저장’으로 연결합니다. 과거 자료를 이름만으로 자동 연결하지 않았습니다. 잘못된 현장/용도를 수정하면 완료 목록도 바뀝니다. 실제 AI 재호출 없이 기존 결과에 연결할 수 있습니다.

## 데이터와 설치

최초 설치 시 앱 폴더에서 `npm ci`, 그다음 기존 `시작.command` 또는 `npm run app:start`. Node.js 22.20.x 사용. 기존 DB는 시작할 때 migration 014·015를 적용합니다. 실행 중인 앱은 종료 후 다시 시작하고 브라우저를 새로고침하세요.

- `backend/estimate-workbooks.ts`: 엑셀 검증, 시트 읽기, 열 매핑·정규화, 양식.
- `backend/project-plans.ts`: 일정 계산·저장·버전·승인·현장 분류.
- `backend/plan-pptx.ts`: 편집 가능한 PPT 생성.
- `frontend-demo/project-workspace.js`: 엑셀 작성·검토·현장별 목록.
- `frontend-demo/customer-completed.js`: 고객 완료 목록.
- `backend/migrations/014_excel_project_plans.sql`: 원본 견적, 일정 묶음, 버전, 승인 기록.
- `backend/migrations/015_portfolio_prompt_projects.sql`: 프롬프트의 현장·용도.

원본 엑셀은 SQLite BLOB으로, 추출 값/행 번호/선택 매핑/제외 행/계산 결과/승인은 DB에 저장합니다. 파일 해시와 현장 조합으로 같은 엑셀 업로드를 중복 저장하지 않습니다. 데이터는 현장 FK로 연결하고 삭제는 RESTRICT, 버전에는 PK(plan_id, revision)와 승인 FK를 적용합니다. project_id+created_at/updated_at 인덱스를 둡니다. 실제 PPT는 저장된 버전을 기준으로 요청할 때 재생성합니다. 기존 전체 백업 ZIP에 엑셀·일정·승인·현장 연결도 함께 포함되며 별도 엑셀 폴더를 옮길 필요가 없습니다. 공개 시안/호스팅/GitHub에는 개인 DB와 엑셀을 올리지 않습니다.

지원 제한: `.xlsx`만(구형 .xls/암호 파일/매크로/외부 연결 제외), 파일 5MB, 내부 압축 해제 20MB, 10개 시트, 시트 2,000행·60열, 전체 30,000셀, 최종 100품목·30공정, 최대 1년. 수식은 실행하지 않고 저장된 계산 결과만 사용합니다. 단가·합계 계산 또는 견적 원본 변경은 이번 기능에서 수행하지 않습니다. 임의 엑셀의 공종 머리글/병합 구조를 자동 추론하는 기능과 AI 공정 순서 제안은 향후 범위입니다.

## 검증

전체 테스트 36개 통과(2026-11-22). 엑셀 파일 검증·중복·수식 결과·행 제외, 일정 역산·주말·휴무·동시 작업·연도 경계, 승인/반려·재승인·버전 충돌, 현장 격리, 편집 가능한 PPT 구조, 전체 백업·다른 경로 복원, 완료 기준을 검사했습니다. 실제 브라우저에서 가상 엑셀 5품목 업로드→수정→승인→PPT 다운로드와 좌우 현장 이동을 확인했습니다. PPT는 LibreOffice로 렌더링해 달력 배치를 확인했으며 Microsoft PowerPoint 앱 실검증은 하지 않았습니다. Windows 실행은 이번 Mac에서 직접 검증하지 않았습니다.
